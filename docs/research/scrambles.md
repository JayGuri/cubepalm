# Are scrambles uniformly random cubes?

> Generated by `npm run research` (`research/scrambles.study.ts`). Do not edit by hand: change the experiment and run it again.

The app scrambles by drawing a random cube state (`randomCubie` in `src/core/solvers/twoPhase.ts`), solving it and playing the solution backwards. This report tests the state generator for uniformity with chi-square goodness-of-fit tests, checks that it only produces reachable cubes, and describes the length of the scrambles the app actually hands out. The proof that the construction is uniform is in `docs/MATH.md`; this is the empirical check that the code matches the proof.

## Parameters

- seed: 20261011
- states drawn (seeded): 600000
- scrambles drawn (cryptographic source, not seeded): 200
- significance level per test: 0.1% (99.9th percentile critical values)
- runtime: Node v20.19.3

## Reachability

Of 600000 generated states, 0 broke a reachability rule (both arrangements valid permutations, corner twists summing to 0 mod 3, edge flips summing to 0 mod 2, corner and edge permutation parities equal).

Counting the states the way the generator draws them, 8! x (12! / 2) x 3^7 x 2^11 = 43,252,003,274,489,856,000.

## What this does and does not show

- It shows that nine one-dimensional features of the generated states are consistent with uniformity, and that no generated state was unreachable. With nine tests at the 0.1% level, a perfectly uniform generator would still fail at least one of them in up to 0.9% of seeds.
- A chi-square test cannot prove uniformity over every reachable state: no sample can. It can only fail to find a bias in the features it looks at. The argument that there is none is the proof in `docs/MATH.md`.
- The tests use a seeded generator in place of the cryptographic one, so they test the construction (shuffle, parity fix, computed last twist and flip), not the quality of `crypto.getRandomValues`.
- The scramble-length figures describe this solver at this time budget on one machine (Node, one thread); a faster machine finds slightly shorter solutions in the same time.
